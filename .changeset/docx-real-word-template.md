`witify-docx` now ships the brand as a real Word template, `witify-template.docx`, instead of rebuilding it in code on every run. The generator script only writes content with the template's named styles, and every cover line is live Word text rather than pixels in a rasterized image, so a reviewer can fix a typo in Word. The only runtime dependency left is `python-docx`. The template itself is regenerated by a maintainer script under `.agents/witify-docx/`.

The cover is redesigned: a grained teal gradient around `#1D373D`, a version line above the title, and a prepared-for / prepared-by block (client, date, author) at the bottom. The output file is named `<title> - v<version>.docx`. Every content page carries a thin teal band flush with its top edge.

Typography moves to Helvetica for text (bundled with macOS, Arial on Windows) and Archivo bold for headings and the cover title. Archivo Bold is bundled with the skill and installed into the user's font folder on first run. Tables get a default `Witify Table` style: bold header row on light gray with a dark bottom rule, thin gray rules between rows, no vertical borders.

The skill now opens by proposing the cover values (title, subtitle, version, client, date, author, table of contents) in a single confirmation table before building anything, and a `TOC` option inserts a "Table des matières" page with a Word TOC field after the cover.
