## What it does

Generates a polished, Witify-branded Word document from a real Word template: a full-page dark cover (soft teal gradient with fine grain, light logo, red accent, tone-on-tone W watermark, a version line above the title and a prepared-for / prepared-by block at the bottom), Helvetica text with Archivo bold headings, the gray W icon in every header, and a `Witify Technologies · witify.io` footer with right-aligned page numbers. The agent never styles anything — it opens `witify-template.docx`, fills the cover placeholders, and writes content using only the template's named styles, so the brand decisions (and the Word quirks they defeat) are already baked into the file. It opens by confirming the cover values (title, subtitle, version, client, date, author, whether a table of contents is wanted, and whether the document gets diagrams) in a single table before it builds anything. Diagrams are drawn by the companion `diagram-design` plugin, exported to PNG, and dropped in as numbered figures with a gray caption that stays on the same page. The build script installs the committed Witify diagram profile into `~/.diagram-design/profiles/` and writes a `.diagram-design` marker in the document folder, so diagram-design picks up the brand (white paper, red accent, Archivo titles, Helvetica labels) without any onboarding step.

## When to reach for it

Type `/witify-docx`, or the agent reaches for it automatically when a deliverable needs to ship as a Word document with Witify branding — a client-facing requirements doc, a proposal, a report.

## Prerequisites

`python-docx` — one pip install, no browser, no fonts on the generating machine, so it runs wherever the agent does, macOS or Linux sandbox alike. Body text is Helvetica, bundled with macOS and substituted by Arial on Windows; Archivo Bold for headings is bundled with the skill and installed automatically on first run, and a reader who opens the .docx on a machine without it sees a substitute, so that font is the only thing to install client-side. Verification needs LibreOffice (and `pymupdf` to rasterize its PDF). Figures are optional and need the third-party [diagram-design](https://github.com/cathrynlavery/diagram-design) plugin plus Playwright with Chromium for its PNG export; install commands for Claude Code and Codex are in the README's [Recommended Companions](https://github.com/witify/skills#recommended-companions) section, and the skill points you there when it proposes diagrams and the plugin is missing rather than installing it itself.

## The template is the brand

The skill's discipline is **template, not taste**: every document starts from `witify-template.docx`, a Word file that already holds the styles, the cover, the header and the footer, so two documents produced months apart look like they came from the same shop. The generator script is under a hundred lines and only knows how to write content; the non-obvious Word mechanics learned the hard way (theme fonts that override explicit ones, heading styles that stay blue, footer tab stops that ignore the page edge) live once in the template, regenerated by a maintainer script in `.agents/witify-docx/`. Cover text is live Word text, so a reviewer can fix a typo without re-running anything.

The loop ends with a **visual verification pass**: the docx is converted to PDF, every page rendered to an image, and each one inspected before the document is declared done.

## It's working if

- The document opens in Word with Helvetica body text and Archivo bold headings — no Calibri, no theme blue.
- The cover is a full-bleed dark page matching the Witify site's palette, with the title as editable text, with the version line and the prepared-for / prepared-by block.
- Content pages carry a thin teal band flush with the top edge, the gray W icon top-right and a right-aligned page number starting at 1 after the cover.
- The agent showed rendered page images before calling it done.
